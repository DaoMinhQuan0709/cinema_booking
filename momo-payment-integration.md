# Kế hoạch tích hợp thanh toán MoMo

Hoàn thiện luồng Checkout → MoMo Sandbox → xác nhận thanh toán → cấp vé, xử lý an toàn khi khách hủy, mất kết nối hoặc IPN đến muộn.

Hiện có: `MoMoConfig`, `PaymentGateway.createMoMo`, IPN, `PaymentAttempt` và lựa chọn MoMo tại checkout. Còn thiếu: trang kết quả MoMo, đối soát tự động và kiểm thử merchant Sandbox thật.

Phạm vi: thanh toán ví một bước qua trang MoMo (`captureWallet`, `autoCapture=true`), tận dụng Spring Boot/Java HttpClient và React hiện có. Production, QR nhúng và hoàn tiền tự động dành cho kế hoạch tiếp theo.

## Công việc theo thứ tự phụ thuộc

- [ ] **1. Cấu hình merchant** — Bỏ khóa demo mặc định trong `MoMoConfig.java`; kiểm tra đủ partner/access/secret, placeholder, khoảng trắng và URL trong `PaymentGateway.validate`. Bổ sung mẫu cấu hình bằng biến môi trường; khóa thật chỉ lưu tại máy. → Kiểm tra: thiếu cấu hình bị chặn trước khi tạo attempt.
- [ ] **2. Hoàn thiện tạo phiên** — Chuẩn hóa request/response, HMAC-SHA256, giới hạn VND nguyên và HTTPS allowlist trong `PaymentGateway.java` theo [Create API](https://developers.momo.vn/v3/vi/docs/payment/api/wallet/onetime/). → Kiểm tra: response hợp lệ chỉ tạo `READY`; ID/amount/chữ ký sai hoặc thiếu `payUrl` không chuyển trang hay xác nhận vé.
- [ ] **3. Chuẩn hóa kết quả giao dịch** — Trong `CheckoutPaymentService.java`/`PaymentServiceImpl.java`, phân biệt lỗi tạo phiên, kết quả thanh toán cuối và trạng thái chờ theo [result codes](https://developers.momo.vn/v3/docs/payment/api/result-handling/resultcode/), gồm `1000`, `7000`, `7002`, `9000` theo chế độ capture. → Kiểm tra: timeout giữ `UNKNOWN` và ID cũ; chỉ thất bại cuối đã xác minh mới cho thử lại trong hạn giữ ghế.
- [ ] **4. Hoàn thiện IPN** — Sửa `PaymentController.java`, DTO và xử lý IPN: xác minh chữ ký, merchant, method, order/request ID, amount, transId; IPN hợp lệ hoặc lặp trả **204**, lỗi xác minh không cập nhật DB, lỗi xử lý không ACK thành công. → Kiểm tra: phản hồi dưới **15 giây**, không cấp vé hai lần; đối chiếu [hợp đồng IPN](https://developers.momo.vn/v3/docs/payment/api/result-handling/notification/).
- [ ] **5. Đối soát khi thiếu IPN** — Thêm `MoMoReconciliationService`, scheduler và metadata/index cần thiết trong `PaymentAttempt` cùng `db/manual/momo-payment.sql`: gọi [Query API](https://developers.momo.vn/v3/vi/docs/payment/api/payment-api/query/) ngoài transaction, timeout ≥30 giây, backoff/giới hạn lượt; query dùng order ID cũ và request ID riêng. → Kiểm tra: quét cả đơn đã hết hạn/hủy còn kết quả chưa rõ; query/IPN dùng chung settlement có khóa, không ghi đè thành công; không thể cấp ghế thì `REFUND_REQUIRED` và có hướng dẫn đối soát thủ công.
- [ ] **6. API kết quả MoMo** — Thêm `POST /api/v1/payments/momo-return` trong `PaymentController`/`PaymentReturnService`, DTO và truy vấn attempt theo method. → Kiểm tra: chữ ký/ID/amount hợp lệ, chỉ owner/admin xem được, `Cache-Control: no-store`; return chỉ đọc, không xác nhận thanh toán từ trình duyệt.
- [ ] **7. Trang kết quả** — Thêm `MoMoReturnPage.jsx`, parser/utils, route `/payment/momo-callback` trong `frontend/src/App.jsx` và hàm gọi API trong `services/paymentService.js`; tái sử dụng giao diện VNPay phù hợp. → Kiểm tra: đăng nhập lại/reload vẫn xem được; polling 3 giây tối đa khoảng 1 phút rồi kiểm tra thủ công; phân biệt chờ/hủy/lỗi/hoàn tiền; thành công khi DB có `CONFIRMED` + `SUCCESS`.
- [ ] **8. Hướng dẫn chạy** — Cập nhật `backend/cinema-booking-backend/CHECKOUT.md`: cấu hình F5, migration, merchant/app test, return frontend và IPN backend HTTPS public qua domain/tunnel. → Kiểm tra: phân biệt nhả ghế với hủy giao dịch tại MoMo; có cách xử lý giao dịch chưa rõ mà không yêu cầu trả tiền lại.
- [ ] **9. Kiểm chứng tự động** — Bổ sung test MoMo vào gateway/return/IPN/reconciliation, PostgreSQL và `frontend/scripts/checkout-browser-check.mjs`. → Chạy `./mvnw.cmd '-Dtest=PaymentGatewayTests,PaymentReturnTests,MoMoPaymentTests,CheckoutPostgresTests,RedisHoldTokenTests' test` tại backend; tại frontend chạy `npm.cmd test`, `npm.cmd run lint`, `npm.cmd run build`, `npm.cmd run test:checkout-browser`. Bao phủ chữ ký giả, sai số tiền/quyền, request lặp, timeout, query đua IPN và tranh chấp ghế; test hạ tầng phải thực chạy, không tính skip là đạt.
- [ ] **10. Kiểm chứng Sandbox thật** — Khi có merchant hợp lệ và IPN HTTPS public, thử thành công, từ chối/hủy, đóng tab và IPN trễ; các lỗi mạng khó tái hiện dùng mô phỏng ở bước 9. → Đối chiếu MoMo với payment/booking/ghế và vé/email; ghi rõ kết quả thật và mô phỏng trong `CHECKOUT.md`.

Hoàn tất khi: thanh toán Sandbox xác nhận và cấp vé đúng một lần; trình duyệt không thể giả thành công; giao dịch chưa rõ được đối soát, giao dịch không cấp được vé được đánh dấu cần hoàn tiền; kiểm thử MoMo và hồi quy VNPay đều đạt.
